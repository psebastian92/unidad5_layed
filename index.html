Qué es la IA

Primero entendemos qué es realmente una inteligencia artificial (sin magia). Después, conectamos una a una app Java de consola. Leé tranquilo: cada parte es corta y va de a poco.

Parte 1 · Entender la IA
01

¿Qué es una IA?

La idea general, antes de cualquier código.

Inteligencia Artificial (IA) es el nombre que le damos a los programas capaces de hacer tareas que antes parecían solo de humanos: entender un texto, reconocer una foto, traducir, responder preguntas.

"IA" es un paraguas enorme. La que vamos a usar nosotros es de un tipo específico, pensado para texto: se llama LLM.

🧩

IA es la categoría grande; LLM es una rama dentro de ella. Como "vehículo" es la categoría y "auto" es un tipo de vehículo.

02

Cómo predice palabras

El secreto de un LLM es más simple de lo que parece.

LLM = Large Language Model = Modelo Grande de Lenguaje. Lo único que sabe hacer es adivinar la palabra que sigue: le das un texto y calcula cuál es la palabra más probable a continuación.

"El cielo está despejado y es de color ___"
azul
86%
gris
9%
rojo
3%

Elige una, la agrega, y vuelve a preguntarse cuál sigue. Repitiendo eso miles de veces arma una respuesta entera. Es parecido al teclado del celular que sugiere la próxima palabra… pero muchísimo más potente.

💡

No "piensa" la respuesta de entrada: la va construyendo palabra por palabra, siempre eligiendo la más probable.

03

La red neuronal

¿Cómo aprendió a adivinar tan bien?

Adentro del LLM hay una red neuronal: muchísimos "nuditos" conectados entre sí, inspirados muy de lejos en las neuronas del cerebro. Cada conexión tiene un número que se puede ajustar.

Durante el entrenamiento, el modelo "leyó" millones y millones de textos de internet y fue ajustando esos números hasta acertar cada vez mejor qué palabra venía después. No memorizó los textos: aprendió los patrones del lenguaje.

🧠

Ojo: no entiende como una persona. Encontró patrones a partir de un montón de ejemplos. Por eso a veces se equivoca con total seguridad.

04

Tokens

La IA no cuenta en palabras: cuenta en tokens.

Un token es un pedacito de texto. A veces es una palabra entera, a veces solo un cacho de palabra. El modelo parte todo en tokens antes de procesarlo:

Inteligencia → 3 tokens cielo → 1 token

Importan por dos razones: las APIs limitan y cobran por tokens, y con max_tokens vas a poder controlar cuánto puede extenderse la respuesta.

05

Empresas, asistentes y modelos

Tres cosas distintas que conviene no mezclar.

La empresa fabrica la IA. El asistente es la app que vos usás (ChatGPT, Claude). El modelo es el "motor" entrenado que está por detrás, y tiene su propio nombre técnico.

EmpresaAsistente que conocésModelo (el motor)
OpenAIChatGPTGPT-5
AnthropicClaudeClaude

MistralLe ChatMistral
🔑

Cuando programes no vas a usar "ChatGPT": vas a pedir un modelo por su nombre técnico, como llama-3.3-70b-versatile. Algunos modelos (como LLaMA, de Meta) son abiertos, así que otras empresas los pueden usar.

06

Qué es Groq

Ojo acá, porque es distinto a todo lo anterior.

Groq no fabrica modelos. Es una empresa que tiene un hardware especial, muy rápido, para ejecutar modelos de otros (LLaMA y compañía).

🏎️

Groq es la pista de carreras (rapidísima); los modelos como LLaMA son los autos. Por eso, al programar, le pegamos a la dirección de Groq pero el modelo que corre es de Meta.

Lo elegimos para la escuela porque es gratis, sin tarjeta de crédito y muy veloz para responder.

⚠️

Groq (con Q) no es lo mismo que Grok (con K, el de la empresa xAI). Se confunden todo el tiempo.

07

Tu API key

La "llave" que te identifica ante el servicio.

Para que Groq sepa que el pedido es tuyo, necesitás una API key: una clave única, como una contraseña. Se saca gratis en pocos minutos.

Pasos en Groq

  1. Entrá a console.groq.com y creá una cuenta (con email o con tu cuenta de Google).
  2. Verificá tu email para poder entrar a la consola.
  3. En el menú, andá a la sección API Keys.
  4. Clic en Create API Key y ponele un nombre (ej: chat-clase).
  5. Copiala al instante y guardala: se muestra una sola vez.
🔒

La API key es como tu contraseña: no se comparte, no se pega en el código, no se sube a GitHub. Si se filtra, hay que darla de baja y crear una nueva.

🆓

¿Otras gratis? Mistral (console.mistral.ai, te pide verificar un teléfono, sin tarjeta) funciona casi igual. Hay varias más; el código de esta guía sirve para cualquiera que use el mismo formato.

09

JSON y las herramientas

El pedido y la respuesta viajan en un formato llamado JSON.

Por dentro, un JSON funciona igual que un HashMap (el de la Unidad 4): guarda datos como pares clave → valor y buscás cada dato por su clave. Por ejemplo, la clave "role" tiene el valor "user". La diferencia es que un JSON es además un String: está escrito como texto, y por eso puede viajar por internet en el pedido y la respuesta.

🔁

Por eso más adelante el .getString("content") te va a sonar conocido: es pedir un valor por su clave, igual que el get(clave) del HashMap.

Para armar y leer JSON en Java sumamos una herramienta externa, org.json (un archivo .jar que se agrega al Build Path en Eclipse). Para conectarse a internet usamos HttpClient, que ya viene con Java (desde la versión 11): no se instala nada.

imports
import java.net.http.*;   // HttpClient — viene con Java
import java.net.URI;       // la dirección a la que pedimos
import org.json.*;         // JSONObject y JSONArray — herramienta externa
✅

org.json es el único agregado externo. Todo lo demás ya viene con Java.

10

La clave, afuera del código

La API key del paso 07 no se escribe en el programa. Se guarda en una variable de entorno de la compu (la llamamos GROQ_API_KEY) y desde el código la leemos con System.getenv:

así se usa la clave
.header("Authorization", "Bearer " + System.getenv("GROQ_API_KEY"))
🔐

Así el código se puede mostrar y compartir tranquilo: la clave vive en la máquina, no adentro del programa.

Dónde la cargás en Eclipse

En Eclipse, esa variable de entorno se carga en la configuración de ejecución de tu programa:

  1. Menú Run → Run Configurations…
  2. Elegí tu clase a la izquierda y abrí la pestaña Environment.
  3. Clic en Add. En Name poné GROQ_API_KEY y en Value, tu clave.
  4. Apply y Run. Listo: el programa ya puede leerla con System.getenv.
11

Los tres roles de la charla

Una conversación con la IA no es un solo texto: es una lista de mensajes. Cada mensaje lleva dos etiquetas: role (quién habla) y content (qué dice). Los roles posibles son tres, y cada uno cumple una función distinta:

system

La instrucción de arranque, la que vos controlás como programador. Le fija a la IA quién es, cómo tiene que hablar y qué sabe. Se escribe una sola vez, al principio, y el usuario no la ve.

user

Cada cosa que escribe la persona en la consola: su pregunta o pedido del momento. Se agrega un mensaje user por cada turno.

assistant

La respuesta que devuelve la IA. La guardamos en la lista para que, en el próximo pedido, la IA "recuerde" lo que ya dijo y la charla tenga continuidad.

Esa lista la guardamos en un ArrayList de JSONObject — lo mismo de la Unidad 4. Cada mensaje es un JSON chiquito con sus dos etiquetas:

el historial
ArrayList<JSONObject> historial = new ArrayList<>();

historial.add(new JSONObject()
    .put("role", "system")
    .put("content", "Sos un asistente simpático que responde en español. Sos conciso y directo."));
12

Armar y mandar el pedido

Armamos un JSON con tres datos que Groq espera: model (qué modelo), max_tokens (largo máximo) y messages (toda la charla). Después lo manda HttpClient.

consultarGroq()
JSONArray mensajes = new JSONArray();
for (JSONObject msg : historial) {
    mensajes.put(msg);
}

String requestBody = new JSONObject()
    .put("model", "llama-3.3-70b-versatile")
    .put("max_tokens", 1000)
    .put("messages", mensajes)
    .toString();

HttpClient client = HttpClient.newHttpClient();
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.groq.com/openai/v1/chat/completions"))
    .header("Authorization", "Bearer " + System.getenv("GROQ_API_KEY"))
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString(requestBody))
    .build();

HttpResponse<String> response = client.send(request,
    HttpResponse.BodyHandlers.ofString());
✅

Mandamos todo el historial en cada pedido: eso es lo que le da memoria a la conversación.

14

El loop con memoria

El programa repite: pide un mensaje, consulta, muestra. La clave está en cuándo agregamos cada mensaje al historial.

main()
while (true) {
    System.out.print("Vos: ");
    String input = scanner.nextLine();
    if (input.equalsIgnoreCase("salir")) break;

    // 1) el mensaje del usuario, ANTES de consultar
    historial.add(new JSONObject().put("role", "user").put("content", input));

    String respuesta = consultarGroq(historial);
    System.out.println("Groq: " + respuesta + "\n");

    // 2) la respuesta de la IA, DESPUÉS de recibirla
    historial.add(new JSONObject().put("role", "assistant").put("content", respuesta));
}
⚠️

Si te olvidás de estos dos add, la IA pierde la memoria: cada respuesta arrancaría de cero.

★

El programa completo

Todas las piezas juntas. (El wrapTexto es un extra de presentación: corta las respuestas largas para que se lean cómodas en la consola — no tiene nada que ver con la IA.)

ChatIA.java
package A;

import java.net.http.*;
import java.net.URI;
import java.util.ArrayList;
import java.util.Scanner;
import org.json.*;

public class ChatIA {

    // Un solo Scanner para todo el programa: lee lo que el usuario escribe en la consola
    static Scanner scanner = new Scanner(System.in);

    // ===================== WRAP (solo presentación) =====================
    // Corta el texto largo en varias líneas. NO tiene que ver con la IA: es para que se lea cómodo.

    static String wrapTexto(String texto, int ancho) {
        StringBuilder sb = new StringBuilder();        // donde vamos armando el texto final
        String[] palabras = texto.split(" ");          // separa la respuesta en palabras
        int lineaActual = 0;                           // cuántos caracteres llevamos en la línea
        for (String palabra : palabras) {              // recorremos palabra por palabra
            if (lineaActual + palabra.length() > ancho) {  // si la línea se pasa del ancho...
                sb.append("\n      ");                 // ...salto de línea y sangría
                lineaActual = 6;                       // reiniciamos el contador (la sangría ocupa 6)
            }
            sb.append(palabra).append(" ");            // pegamos la palabra y un espacio
            lineaActual += palabra.length() + 1;       // sumamos lo que ocupó (palabra + espacio)
        }
        return sb.toString().trim();                   // devolvemos el texto ya formateado
    }

    // ===================== API =====================
    // Recibe el historial de la charla y devuelve la respuesta de la IA como texto

    static String consultarGroq(ArrayList<JSONObject> historial) throws Exception {

        // Pasamos la lista de mensajes a un JSONArray (el formato que viaja a Groq)
        JSONArray mensajes = new JSONArray();
        for (JSONObject msg : historial) {
            mensajes.put(msg);
        }

        // Armamos el cuerpo del pedido: qué modelo, largo máximo y la conversación entera
        String requestBody = new JSONObject()
            .put("model", "llama-3.3-70b-versatile")   // qué modelo de IA usamos
            .put("max_tokens", 1000)                   // largo máximo de la respuesta
            .put("messages", mensajes)                 // todos los mensajes de la charla
            .toString();                               // lo convertimos a texto para enviarlo

        HttpClient client = HttpClient.newHttpClient();            // el "cartero" que lleva el pedido
        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("https://api.groq.com/openai/v1/chat/completions"))  // a dónde lo mandamos
            .header("Authorization", "Bearer " + System.getenv("GROQ_API_KEY"))  // la clave, leída de afuera
            .header("Content-Type", "application/json")            // avisamos que mandamos JSON
            .POST(HttpRequest.BodyPublishers.ofString(requestBody))// método POST con el cuerpo armado
            .build();                                              // construimos el pedido

        // Enviamos y esperamos la respuesta como texto
        HttpResponse<String> response = client.send(request,
            HttpResponse.BodyHandlers.ofString());
        JSONObject json = new JSONObject(response.body());  // convertimos el texto de respuesta en JSON
        // "Entramos" al JSON capa por capa hasta el texto que nos interesa
        return json.getJSONArray("choices")   // lista de respuestas
                   .getJSONObject(0)           // la primera
                   .getJSONObject("message")   // su mensaje
                   .getString("content");      // el texto final de la IA
    }

    // ===================== MAIN =====================

    public static void main(String[] args) throws Exception {

        // El historial guarda TODA la conversación (cada mensaje con su rol)
        ArrayList<JSONObject> historial = new ArrayList<>();

        // Primer mensaje: define la personalidad de la IA. Se manda una sola vez.
        historial.add(new JSONObject()
            .put("role", "system")
            .put("content", "Sos un asistente simpático que responde siempre en español. Sos conciso y directo."));

        System.out.println("=== CHAT CON GROQ ===");
        System.out.println("(escribí 'salir' para terminar)\n");

        while (true) {                                 // bucle: chateamos hasta que el usuario corte
            System.out.print("Vos: ");
            String input = scanner.nextLine();         // leemos lo que escribe el usuario

            if (input.equalsIgnoreCase("salir")) {     // si escribió "salir", cortamos
                System.out.println("Groq: ¡Hasta luego!");
                break;
            }

            // Agregamos el mensaje del usuario ANTES de consultar
            historial.add(new JSONObject()
                .put("role", "user")
                .put("content", input));

            String respuesta = consultarGroq(historial);         // le pasamos la charla y pedimos respuesta
            System.out.println("Groq: " + wrapTexto(respuesta, 80) + "\n");  // la mostramos formateada

            // Agregamos la respuesta de la IA DESPUÉS de recibirla (así "recuerda" lo dicho)
            historial.add(new JSONObject()
                .put("role", "assistant")
                .put("content", respuesta));
        }
    }
}

Puesta en marcha (paso a paso)

Tenés todas las piezas. Ahora, cómo dejar el programa andando desde cero.

Paso 1 · Descargar la librería org.json

Es el archivo .jar que le da a Java las herramientas JSONObject y JSONArray. Lo bajás de internet:

  1. Entrá a github.com/stleary/JSON-java y buscá el link que dice "the latest release jar file" (te lleva al .jar más nuevo).
  2. Se descarga un archivo con nombre tipo json-20260101.jar (los números son la fecha de la versión; cualquiera reciente sirve).
  3. Guardalo en un lugar que después encuentres; por ejemplo, una carpeta lib dentro de tu proyecto.

Paso 2 · Agregar el .jar al Build Path

📦

¿Qué es el Build Path? Es la lista de herramientas que tu proyecto tiene permiso de usar. Java, solo, no sabe qué es un JSONObject: eso viene en org.json. Agregar el .jar al Build Path es avisarle a Java "esta herramienta también la voy a usar", para que reconozca JSONObject y JSONArray sin marcarte error.

  1. En Eclipse, clic derecho sobre tu proyecto (en el panel de la izquierda).
  2. Elegí Build Path → Configure Build Path…
  3. Andá a la pestaña Libraries, seleccioná Classpath y clic en Add JARs… (si el .jar está dentro del proyecto) o Add External JARs… (si está en otra carpeta).
  4. Buscá y elegí tu json-XXXXXXXX.jar, y dale Apply and Close.
✅

Si quedó bien, el import org.json.*; de arriba de tu clase deja de aparecer subrayado en rojo.

Paso 3 · Generar tu API key

Seguí los pasos de la sección 07: entrás a console.groq.com, creás la cuenta, vas a API Keys → Create API Key y copiás la clave (se muestra una sola vez).

Paso 4 · Cargar la clave en Eclipse

Como vimos en la sección 10, la clave no va en el código sino en la configuración de ejecución:

  1. Menú Run → Run Configurations…
  2. Elegí tu clase y abrí la pestaña Environment.
  3. Add → Name: GROQ_API_KEY · Value: tu clave.
  4. Apply.

Paso 5 · Ejecutar

Pegá el código completo en tu clase y dale Run (el triángulo verde ▶). Si todo está bien, vas a poder chatear con la IA desde la consola.

🔧

¿No anda? Revisá tres cosas: que el .jar esté agregado al Build Path (Paso 2), que el nombre GROQ_API_KEY esté escrito igual en Environment y en el código, y que hayas pegado la clave completa, sin espacios.
